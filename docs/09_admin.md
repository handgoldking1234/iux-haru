# 09. 관리자 페이지 기능 분석

**결론: 출시 전에 필요하다.** 학습 앱은 출시 후 할 일이 세 가지다.
1. 아이들이 매일 돌아오는지 보는 것
2. 콘텐츠 오류를 고치는 것
3. 보호자 문의와 아동 개인정보를 처리하는 것

이 셋은 DB를 직접 열어서 할 수 없다. 다만 처음부터 다 만들 필요는 없다. 아래 우선순위대로 나눠 만든다.

## 1. 메뉴 구조

| 메뉴 | 핵심 화면 | 우선 |
| --- | --- | --- |

## 2. 대시보드

### 2-1. 핵심 지표 카드 (오늘 / 어제 대비 / 7일 평균)
- **가입**: 신규 보호자, 신규 학생(자녀 프로필).
- **활성 학생**: DAU, WAU, MAU. DAU/MAU 비율(습관 지표)도 본다.
- **오늘 할 일 완료율**: 오늘 할 일을 다 끝낸 학생 ÷ 오늘 활성 학생. **가장 중요한 지표**다.
- **학습량**: 학생 1인당 푼 문제 수, 학습 시간(분), 정답률.
- **재방문율**: D1·D7·D30 (가입 주차 코호트).
- **연속 학습일**: 3일 이상, 7일 이상인 학생 수.
- **매출**(결제 오픈 후): 유료 가족 수, 전환율, MRR, 해지율.
- **품질**: 오늘 들어온 오류 신고와 문의 건수.

### 2-2. 차트
- 일별 DAU와 오늘 할 일 완료율 (90일 선 그래프).
- 가입 코호트 재방문 표 (주차 × D1·D7·D14·D30).
- 과목별 일일 풀이 수 (누적 막대).
- 시간대별 학습 분포. 알림 시간(16·20시)이 효과가 있는지 확인한다.
- 학년별 활성 학생 분포 (초1~고3).

### 2-3. 이상 알림
- 특정 문항 정답률이 같은 단원 평균보다 30%p 이상 낮으면 오류를 의심한다.
- 하루 오류 신고가 급증하면 알린다.
- 캐시나 랭킹에서 비정상 증가(부정 사용 의심)가 보이면 알린다.

### 2-4. 지표 정의 (먼저 합의할 것)
- **활성 학생**: 하루에 문제를 1개 이상 풀었거나 슬라이드 카드를 5장 이상 본 학생. 로그인만 한 경우는 넣지 않는다.
- **재방문(Dn)**: 첫 학습일 기준 n일째에 활성인 비율.
- **오늘 할 일 완료**: `daily.bonus = true` (hgs의 '오늘 할 일 완료 +20'이 지급된 날).

## 3. 유입 분석

### 3-1. 수집 방법
- 첫 방문 때 `utm_source / utm_medium / utm_campaign / utm_content`, referrer, 랜딩 페이지, 추천(초대) 코드를 저장한다. 1st-party 쿠키에 30일 보관한다.
- 가입할 때 이 값을 보호자 계정의 `acquisition`에 붙인다. **첫 접점**과 **마지막 접점**을 둘 다 남긴다.
- 기기·OS·브라우저, 시·도 수준 지역을 남긴다. IP 원문은 보관하지 않는다.
- 채널을 미리 정해 둔다:
  - 맘카페·학부모 커뮤니티, 블로그, 인스타그램, 유튜브, 네이버 검색 광고, 지인 추천(초대 코드), 학원 제휴, 직접 방문.

### 3-2. 화면
- **채널별 표**: 방문 → 가입 → 첫 문제 → 오늘 할 일 첫 완료 → D7 재방문 → 유료.
- **퍼널 차트**: 단계별 남은 수와 이탈률.
- **캠페인별 성과**: 비용을 직접 입력하면 가입당 비용(CPA)을 계산한다.
- **추천 코드 순위**: 코드별 가입 수. 요금제 안 A(코드 3개로 과목 열기)를 고르면 필수다.

## 4. 회원 관리

### 4-1. 보호자 목록
- 칸: 이메일(마스킹 `ab***@gmail.com`), 가입일, 가입 경로, 자녀 수, 구독 상태, 최근 학습일, 상태(정상·정지·탈퇴 예정).
- 검색은 이메일, 자녀 닉네임, 추천 코드로 한다. 필터는 기간, 경로, 구독, 활성 여부다.
- CSV 내보내기는 최고 관리자만 할 수 있고, 내보낼 때마다 기록을 남긴다.

### 4-2. 보호자 상세
- 계정: 가입·동의 기록(법정대리인 동의 일시·방법), 로그인 기록, 알림 수신 동의.
- 자녀별:
  - 닉네임, 학년.
  - 과목별 진도(현재 단원), 최근 30일 학습 달력, 정답률, 오답 카드 수.
  - 캐시, 등급, 꾸미기.
- 조치:
  - 비밀번호 재설정 메일 보내기, 계정 정지, 탈퇴 처리.
  - 캐시 보정(사유 필수).
  - 진도 초기화. 보호자가 요청했을 때만 하고 기록을 남긴다.
- 문의 내역, 결제 내역.

### 4-3. 개인정보 원칙 (만 14세 미만 포함)
- 자녀에게서는 **닉네임과 학년만** 받는다. 실명, 학교, 사진, 위치는 받지 않는다.
- 관리자 화면에서도 이메일은 기본으로 가린다. '보기'를 누르면 열람 기록을 남긴다.
- 탈퇴하면 즉시 비활성화하고, 정한 기간이 지나면 파기한다. 결제 기록은 법정 보관 기간을 따른다.
- 분석 도구에는 학생을 식별할 수 없는 ID만 보낸다. 광고 추적 픽셀은 학생 화면에 넣지 않는다.

## 5. 학습 분석
- **과목·단원 표**: 진입 학생 수, 통과율, 평균 통과 시간(일), 틀림 상한 재시작 비율, 승급 평가 통과율.
- **이탈 지점**: 마지막으로 머문 단원 분포를 본다. 예: 연산 받아올림, 한자 6급Ⅱ처럼 갑자기 어려워지는 구간을 찾는다.
- **문항 분석**: 문항·유형별 정답률, 평균 풀이 시간, 오답 보기 분포. 한 오답 보기에 몰리면 문제가 애매하다는 신호다.
- **오답노트 효과**: 1·3·5일 카드의 졸업률.
- **슬라이드·단어장·검색**
  - 슬라이드 덱 완주율과 받아쓰기 사용 수.
  - 단어장 담기 상위 단어.
  - 검색어 상위 목록. 결과 0건 검색어는 콘텐츠를 보강할 후보로 본다.
- **보호자 설정 분포**: 오늘 할 일 분량, 게임 판 수, 밤 잠금 사용률.

## 5-1. 게임 이용 분석
게임이 공부를 끝내게 만드는 보상으로 제대로 작동하는지 본다.
- **핵심 지표**
  - 게임한 학생 비율: 게임이 열린 학생 중 실제로 게임한 비율. 낮으면 보상 매력이 약하다는 뜻이다.
  - 게임 열린 학생 비율(= 오늘 할 일 완료율), 1인당 판 수, 1인당 게임 시간과 학습 시간 대비 비율.
  - '+1판' 받으려고 할 일 뒤 20문제를 더 푼 학생 비율.
  - 만든 대결방 수, 평균 인원, 비공개 비율. 게임 캐시 지급량과 하루 상한(30) 도달 비율.
- **게임별 표**(스피드·대결방·종합 대결·산성비 타자): 판 수, 플레이 학생, 1인당 판, 평균 기록, 평균 시간, 정답률, 재도전율.
- **스피드 게임 과목 분포**: 어떤 과목으로 게임을 많이 하는지 본다.
- **게임한 학생과 안 한 학생 비교**: 할 일 완료율, 하루 푼 문제, D7 재방문, 연속 학습. 함께 나타나는 차이일 뿐 원인이라고 단정하지 않는다고 화면에 적는다.
- **잠금 화면을 본 횟수**: 할 일 미완료, 횟수 소진, 밤 9시, 밀린 공부. 보호자 설정 분포(1·3·5판, 밤 잠금).
- **타자 속도 순위**와 **이상 기록**: 같은 보호자의 자녀 계정끼리 반복 대결, 비정상 타수(붙여넣기 의심), 지나치게 빠른 풀이(찍기 의심). 확인 전까지 랭킹에서 숨긴다.
- **수집 이벤트**: game_play(mode, subject, score, ms, acc), game_locked(reason), room_create(public), room_join, room_result(win), bonus_play_earned.

## 6. 콘텐츠 관리 (CMS)
- 과목 → 갈래 → 단원 → 항목 트리. 항목과 객관식을 수정하면 **슬라이드 카드 미리보기**로 바로 확인한다.
- **검수 상태**: 초안 → 검수 중 → 승인. 지금 데이터 대부분은 AI 작성이라 처음엔 '검수 중'으로 넣는다. 승인한 항목에 배지를 표시하는 것을 검토한다.
- **오류 신고 큐**: 학생·보호자가 신고한 문항, 신고 수, 정답률을 보여 준다. 처리는 수정·반려·답변 중 하나로 하고, 신고자에게 결과를 알린다.
- 변경 이력과 되돌리기. JSON·CSV 일괄 업로드(`07_data.md` 형식).
- 음성 파일 다시 만들기. 항목을 고치면 해당 TTS를 자동으로 다시 만든다.
- 검색 색인 다시 만들기.

## 7. 보상·게임 운영
- **꾸미기 아이템**: 이름, 슬롯, 가격(캐시), 노출 여부, 시즌·한정 기간.
- **캐시 지급·회수**: 개별 또는 일괄(이벤트). 사유와 처리자를 기록한다.
- **랭킹**: 주간 초기화 확인. 하루 상한을 넘거나 같은 패턴이 반복되는 계정을 모아 본다.
- **대결방**: 진행 중인 방 수와 신고된 방. 채팅은 정해진 문구만 쓰므로 문구 목록만 관리한다.
- 규칙 숫자(캐시 상한, 오늘 할 일 기본값 등)는 화면에서 보여 주기만 한다. 바꾸려면 기획 결정과 배포를 거친다(`03_rules.md`).

## 8. 고객지원 · 알림
- 문의함: 분류(로그인·결제·콘텐츠 오류·기타), 담당자, 상태, 답변 템플릿.
- 공지: 앱 안 배너와 공지 목록.
- 푸시·이메일 발송: 대상(전체, 비활성 7일, 특정 학년), 예약, 발송 결과(열람률). 보호자에게만 보낸다.

## 11. 구현 방식
- **1차(출시)**: Next.js 같은 앱 안 `/admin` 경로. Supabase Auth의 관리자 역할과 RLS로 막는다.
  - 대시보드는 DB 집계 뷰(일별 materialized view)로 만든다.
  - 원본 데이터 확인과 응급 수정은 Supabase Studio를 쓴다.
- **분석 도구**: 유입·퍼널은 PostHog(셀프호스팅 가능, 퍼널·코호트 기본 제공) 또는 GA4를 쓴다. 학습 지표는 자체 DB로 계산한다. 학생 식별 정보는 외부 도구에 보내지 않는다.
- **화면 구성**: 왼쪽 메뉴, 상단 기간 선택(오늘·7일·30일·직접), 지표 카드, 차트, 표 순서. 앱과 같은 UI 규칙(`05_ui_guide.md`)을 쓰되 데스크톱 우선, 최대 폭 1440px.

## 13. 화면 시안
- `prototype/admin/index.html`: 마크업과 간단한 스크립트로 만든 시안이다. 숫자는 모두 **예시 데이터**다.
- 들어 있는 메뉴: 대시보드, 유입 분석, 회원(목록·상세 서랍·조치 확인), 학습 분석, 게임 이용, 콘텐츠(오류 신고 큐·항목 수정·학생 화면 미리보기), 고객지원(문의함·푸시 예약), 보상·게임(아이템·캐시 지급·규칙 값), 결제(오픈 전 안내), 관리자·권한(계정·역할표·감사 로그).
- 반응형이다. 860px 이하에서는 메뉴가 서랍으로 바뀌고, 700px 이하에서는 차트를 좁은 비율로 다시 그린다. 밝은 테마와 어두운 테마를 모두 지원한다.
- 관리자 강조색은 홈(놀이터) 색 #DB2777이다.
- **로그인**: 이메일·비밀번호 → 2단계 인증(6자리, 붙여넣기·자동 넘김) → 관리자 화면. 시안은 아무 비밀번호(4자 이상)와 아무 6자리로 들어간다. 로그인 상태는 브라우저 세션에만 남는다. 실제로는 Supabase Auth + 관리자 역할 확인 + TOTP 2단계 인증으로 만든다.
- **오른쪽 위 내 계정**: 누르면 이름·이메일·역할·2단계 인증 상태·이번/지난 로그인·접속 IP와 메뉴(관리자·권한 보기, 비밀번호 바꾸기, 로그아웃)가 열린다.
- **왼쪽 아래 화면 테마**: 라이트 / 다크 / 자동(기기 설정 따름). 고른 값은 브라우저에 기억한다.
